# synolitic-audit

Проверка синолитических графов (supervised pairwise graphs) на HCP и ABIDE:
что несёт сигнал, что добавляет граф и где границы метода.

Отдельный личный репозиторий. К общему репозиторию команды
(`smiles-synolitic-correction`) отношения не имеет и ничего туда не пишет.

## Что здесь

- `scripts/` — все эксперименты, по одному файлу на вопрос.
- `results/` — выходные JSON каждого прогона, ровно те числа, которые
  использованы в отчёте.

Тяжёлые кэши признаков (`*.npy`, суммарно около 2.4 ГБ) намеренно не
коммитятся: они детерминированно пересобираются из сырых данных
скриптом `scripts/build_cache.py` и `scripts/e_prep.py`.

## Сиды и детерминизм

- Разбиения: `GroupKFold` (без перемешивания, детерминирован),
  `RepeatedStratifiedKFold(random_state=0)`, `StratifiedKFold(random_state=0)`.
- Подвыборки субъектов и выбор подмножеств областей: `np.random.default_rng`
  с явным сидом; в лестницах сид задаётся аргументом `--seed` (по умолчанию 0).
- Синтетика: `default_rng(1000 * rep + n)`, то есть повтор `rep` при данном `n`
  воспроизводится точно.
- Парные классификаторы: `LogisticRegression(random_state=0)` у sklearn и
  детерминированный батчевый Ньютон в `fastpair.py`.
- Бутстрэп: `default_rng(seed=0)`, 10000 ресэмплов.

Не зафиксировано: число потоков BLAS, поэтому последние знаки AUC могут
плавать на уровне 1e-6. На выводы это не влияет.

## Карта скриптов

**Инфраструктура**

- `fastpair.py` — батчевая парная логистическая регрессия (демпфированный
  Ньютон, чанки по парам). Эквивалентна sklearn с точностью 0.7% по
  коэффициентам при примерно шестикратном ускорении; проверяется
  `verify_fastpair.py`.
- `build_cache.py` — признаки (среднее, std, корреляции) в float32 на диск.
- `e_prep.py` — логит-перевод и двухфакторное разложение опубликованных графов.
- `agg.py`, `summarize.py` — агрегация результатов и бутстрэп-интервалы.

**Теория и контроли**

- `e5_setup1.py` — теорема о спане на Setup 1: регрессия X на узловой канал.
- `e9_synth.py` — синтетический контроль с нулевым унарным и нулевым узловым
  каналом; логистические рёбра против QDA-рёбер.
- `e11_baselines.py` — высокоразмерные бейзлайны: QDA с усадкой Ledoit–Wolf,
  диагональный QDA, RDA, L1 на попарных произведениях, MLP.
- `e12_controls.py` — контроль со случайным линейным вложением той же ширины.

**HCP**

- `e_channels.py` — каналы на опубликованных графах.
- `e6_rawpath.py` — честный сырой путь: три семейства рёбер, контраст утечки.
- `e7_ladder.py`, `e8_mmp.py` — кривые обучения по n и лестница по d.
- `e10_qda.py` — QDA-рёбра на реальных данных.
- `e13_evoked.py` — снятие вызванного ответа (FIR внутри записи).
- `e14_blockcrop.py` — поблочный кроп против кропа конкатенированного ряда.
- `e17_decompose.py` — разложение узловых сумм на унарную и парную части.

**ABIDE**

- `e15_abide.py` — каналы, две схемы разбиения (по сайтам и по субъектам).
- `e16_abide_protocol.py`, `e18_primary.py` — опубликованный протокол
  (10×5, поправка Надо–Бенжио), с резидуализацией и без неё.
- `e19b_roicurve.py` — точность против числа областей, два порядка отбора.
- `e20_site.py` — движение против идентичности сайта.
